# 有限控件树预算优先保留可见操作

## 目标

修复大目录/列表占满快照预算、挤掉按钮的问题；审查并统一 macOS、Windows、Linux 的遍历策略，不提高默认 1200 节点预算。真实测试后创建 PR、评论 LGTM. Thanks! 并 squash 合并。

## 方案与边界

- 先在有界候选集中按优先级选取节点：可见操作控件、普通可见/未知区域、集合内容、明确不可见内容。集合分支不会抢占其他界面区域。
- 保留祖先路径，按原树顺序渲染选中节点，重建连续索引；动作仍绑定真实 AX/UIA/AT-SPI 对象或路径。
- 候选发现另有预算（默认节点预算的四倍，至少 64、最多 10000），避免为了排序遍历无限列表；深度、循环及 API 错误都需有界。
- macOS 集合有明确可见子项时不再合入完整列表。未知可见性保留，不以全局遮挡判定隐藏；不激活个人应用，不改权限。
- 明确提示截断；无法承诺任意极小预算或任意 provider 都能包含所有控件。

## 验证

- 三平台单测覆盖早出现的大列表、后出现的按钮、可见/隐藏/未知节点、深度、循环、候选上限和索引有效性。
- macOS 签名 native MCP + 真实大目录 NSOpenPanel，操作按钮和点击后的状态；原 main 负对照。
- Linux 私有容器 Xvfb/D-Bus + GTK/AT-SPI，真实大列表及按钮。
- Windows GitHub Actions WPF/UIA/native MCP；等待实际检查结果后合并。
- 运行适用回归、同步架构/使用说明/history，完成 PR 审查。
