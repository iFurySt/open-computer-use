# PR #130：实时焦点与文本输入语义

## 目标

基于最新 main 复核 #130，修复文本输入的缓存焦点和选区回退问题，验证后推送贡献者分支，评论 `LGTM. Thanks!` 并 Squash and merge。

## 边界与风险

- macOS auto 输入每次读取应用当前焦点，读取失败不使用缓存目标；写入前再次确认焦点与会话。
- 优先 AXSelectedText，不要求 AXValue 同时可写。已尝试的写入失败不能再追加或重发文字。
- AXSelectedText 不支持时，仅在值和选区均可写、读到有效 UTF-16 选区并复核文本/选区未变后，通过 AXValue 替换对应范围并恢复光标；否则保留现有进程定向键盘路径，不能盲目追加。
- 空输入不删除选区，UTF-16 边界覆盖 emoji 和中文。显式 sky_key、Windows/Linux 不改变。
- 使用真实 AppKit 文本框、文本区和 sheet，受控文本，不操作用户文档；不改变安装、权限或全局指针设置。

## 实测发现

- 不支持 AXSelectedText 的 AppKit 控件在后台不一定接收 postToPid 键盘回退，因此补充按有效选区写 AXValue 并恢复光标的路径。
- 原 PR 在 AX 当前焦点不可读时仍返回输入成功，负对照已复现；禁止缓存焦点回退。
- UTF-16 替换需要显式拒绝拆开代理对，不能直接依赖 Swift String 范围转换。
