# v1.1.6 patch release

The maintainer requested a patch release after merging #199. Based on main,
this release includes Locked Use recovery when all recorded processes exit
before authorization, macOS text-field and outline click fixes, the Date
interval fix, and Homebrew documentation.

The Broker regression exercises production polling through injected exit
observations. No real lock screen or installed service is used for release
packaging verification. See [execution plan](../../exec-plans/completed/20261123-release-1.1.6.md).

The v1.1.5 legacy npm alias is now available. Its registry tarball SHA-512,
runtime files, strict app signature, and nested notarization tickets passed.
This resolves the previous release's registry visibility follow-up.

Swift passed 510 tests (14 skipped). The release notes, repository checks,
three staged packages, signed universal app and all four Locked Use components
passed. The packaged native executable reports 1.1.6 and passes MCP stdio
notification smoke. The DMG, four native Linux/Windows archives, and public
asset staging checksums also passed.

Xcode 27.2 reproduced a lipo failure when checking two architectures at once.
The release build now checks each requested slice separately. A real universal
artifact passed both checks and a thin ARM artifact correctly failed its
x86_64 check. All signing and notarization requirements remain in place.

The [release workflow](https://github.com/iFurySt/open-computer-use/actions/runs/45200050041)
published v1.1.6 from `e6eafda`. Re-downloading the 10 GitHub Release assets
confirmed the reviewed notes, manifest, checksums, code signatures, nested
notarization tickets, and DMG integrity. Gatekeeper and the shipped MCP
stdio test passed. The universal app archive's provenance verified against
the repository's `release.yml` signer.

The [Homebrew update](https://github.com/iFurySt/homebrew-open-computer-use/actions/runs/45203205917)
published the 1.1.6 cask with the app archive's SHA-256. An isolated Homebrew
install upgraded from 1.1.5 to 1.1.6. Both command names reported 1.1.6,
the installed app's notarization ticket and MCP stdio test passed, and
the isolated cask was uninstalled.

All three npm packages published through OIDC trusted publishing. The public
registry listed 1.1.6 as latest for each. Fresh requests to the public tarball
endpoints verified SHA-512, all runtime targets, strict signing, and nested
notarization tickets. Installing the verified main-package tarball passed the
CLI version check and MCP stdio smoke.

After the initial registry cache delay, a normal version-pinned npm install
with a fresh cache succeeded for all three packages. `npm audit signatures`
verified three registry signatures and three provenance attestations. All
three command versions matched 1.1.6 and the installed main package passed
MCP stdio smoke again.
