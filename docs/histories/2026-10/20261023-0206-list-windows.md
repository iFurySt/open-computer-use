### Changes Overview

**Scope:** macOS `OpenComputerUseKit`、Linux / Windows Go runtime 的参数校验、Node REPL、文档。

- 新增 native `list_windows`：只解析已运行的 app，不启动、不激活、不抬起；按 AX `AXWindows` 返回当前 Space 的窗口，每项包含 `window_id`（与 `query` 相同的 CGWindowID，经现有 `_AXUIElementGetWindow` 绑定得到）、`title`、`subrole`、`focused`、`minimized` 和屏幕坐标 `bounds`。与 `query` 一样在读取前检查会话租约，输出复用 `query` 的 JSON 编码。
- `get_app_state` 新增 `window_id`：用已有的 `windowElement(for:)` 找到该 AX 窗口作为快照根；不走激活 / 抬起的恢复路径，不按标题回退到别的窗口；找不到时报错并提示调用 `list_windows`。
- 绑定会延续到后续回读：service 按进程记住 `window_id`，动作回读与 `sky_key` 的回读继续读该窗口；再次不带 `window_id` 调用 `get_app_state` 即解除；窗口已关闭时回读回到 key window。
- 绑定窗口不是 key window 时，app 的键盘焦点不算这个窗口的焦点：快照不报告它，`type_text` 因此拒绝写入另一个窗口的输入框，而不是静默写进去。`sky_key` 会把按键送到绑定窗口。
- Linux / Windows：不实现 `list_windows`（与 `query`、`select_text` 一样返回 `unsupportedTool`），`get_app_state` 收到 `window_id` 时明确报不支持，不静默忽略。
- Node REPL：`app.listWindows()`，`getAXState({ windowId })`。
- 更新工具清单与描述测试、会话租约测试、参数校验测试，以及 SKILL、usage、js-repl、README、ARCHITECTURE、QUALITY_SCORE 和功能发布记录。

### Design Intent

#83 的第 1 条是缺功能：快照永远绑定 app 的 focused window，调用方既看不到其他窗口，也选不了。`query` 已经接受 `window_id`，这里补上取得 id 的途径，并让 `get_app_state` 用同一个 id 绑定快照。绑定必须覆盖动作回读，否则点击之后的回读会切回 key window 并替换缓存，后续索引又落到另一个窗口，问题原样回来。键盘输入天然跟随 app 的焦点，因此只在焦点不属于绑定窗口时让快照不报告焦点，避免 `type_text` 写错窗口；更大的“窗口作用域索引”不在本次范围。
